# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Firmware (Pico SDK, C) for the **Waveshare RP2040-Touch-LCD-1.69** ("Touch Deck"): three swipeable screens — analog watch with buzzer tick, a device-memory clipboard that *types* its text over USB HID, and a mouse jiggler — plus Python tools in `tools/`.

A second port lives in `esp32c3/` for the **ESP32-2424S012C** (see "ESP32-C3 port" below). The same `src/` tree also builds for the round **Waveshare RP2350-Touch-LCD-1.28** (see "RP2350 round board" below).

The Windows companion app (C# .NET 8 WPF, per-user MSI) is in `windows-app/`. It has its own CLAUDE.md. The macOS app (Swift/SwiftUI menu bar app, same behaviour) is beside it in `macos-app/`, with its own CLAUDE.md; it is a first pass that hasn't been compiled yet (see `docs/HANDOFF.md`). Firmware and apps share one repo so a protocol change can land in a single PR. It replaced the old Python helper (`clip_helper.py`, removed) and bundles `build/watch.uf2` for in-app firmware updates. When you change the protocol in `usb_io.c`/`link.cpp`, update the apps' protocol code too (`TouchDeck.Core/Protocol`, `macos-app/TouchDeckCore/Protocol`). Bump `FW_VERSION` in both `version.h` files so the app offers the update. The app holds the serial port while it runs: quit it (tray → Quit, or `TouchDeck.exe --quit`) before `flash.py`, `perf_rp2040.py` or the board tests.

## Build & flash

Toolchain comes from the VS Code Pico extension in `~/.pico-sdk` (SDK 2.1.1, GCC 14.2, picotool 2.1.1); `CMakeLists.txt` points at it directly, so no `PICO_SDK_PATH` env var is needed. cmake/ninja are not on PATH by default:

```bash
P=~/.pico-sdk; export PATH="$P/ninja/v1.12.1:$P/cmake/v3.31.5/bin:$PATH"
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release   # once
ninja -C build                                            # -> build/watch.uf2
```

Flash: `python tools/flash.py` — sends `BOOT` over the firmware's serial port, waits for the UF2 drive (**J:** here, `INFO_UF2.TXT` says `RPI-RP2`), copies `build/watch.uf2`. No BOOT button needed. It fails if the Windows app is holding the port — quit it first. The firmware enumerates as `CAFE:4011` (composite: CDC + HID keyboard/mouse), not the SDK's `2E8A:000A`, so picotool's reset interface is *not* available; opening the port at 1200 baud also reboots to the bootloader.

Python on this PC: `py` is Python 3.14 and `python` is 3.9 (different package sets; `python -m pip install -r tools/requirements.txt`). The committed `aa_fonts.*` were rendered with Pillow 11.3/FreeType 2.13 (the `python` 3.9 env). Regenerating under 3.14's FreeType 2.14 changes the glyph bitmaps slightly, so regenerate with `python`.

**Releases:** see "Releases and updates" in the README. Tag `app-vX.Y.Z` / `fw-vX.Y.Z` (must equal `<Version>` / `FW_VERSION`); `.github/workflows/release.yml` builds and runs `tools/publish_release.py`, which publishes to the public `SynexyConsulting/TouchDeckUpdates` with a merged `updates.json` (`tools/make_updates.py`, never goes backwards). The ESP32 `.bin` is built but not published until it has run on hardware.

**Tests:** `python -m pytest tools/tests -q`.
- **Unit tests (always run):** the release feed builder, the font generator (every UI label fits its button or circle chord) and the jiggler letters (`test_jigpaths.py`).
- **Host C tests:** `test_jigpaths.py` and `test_gfx_line.py` compile the firmware's own C (`jig_motion.c`, `gfx.c`) into a DLL with MSVC (VS 2022 `vcvars64.bat`, found automatically) and drive it through ctypes. They skip when MSVC is missing.
  - The jiggler tests check that the dot stays in its lane, letters loop or bounce, the mouse stays bounded and switches glide.
  - `test_gfx_line.py` checks `gfx_line` pixel for pixel against the original full-bounding-box algorithm.
  - `test_ui_host.py` builds the device renderers (`hostui/build.bat`) and checks every page of both boards, the panel shapes, the dot, and that `ui_sync.c`'s lines round-trip through the parser (`tdui_host.py`, the Python twin of the app's `MirrorState`).
- **Board tests:**
  - `test_board_mirror.py` (RP2040, firmware 1.7.0+) renders what the board streams after `WATCH 1` on the host and compares it with the board's framebuffer (`FBCRC x y w h`): clipboard, jiggler at every scale and the watch (fb holds second t or the drawn-ahead t+1) must match exactly.
  - `test_board_rp2040.py` drives the RP2040 on COM6 with `SWIPE`, `BTN`, `TAP x y`, `WATCH`/`STATE`, `JIG`, `CLIP CLEAR`, `ANIM` and `DBG` (fields include `jig=`, `jscale=`, `letter=`, `clip=`). Two of its tests turn the jiggler on for about 0.3 s, which moves the real mouse.
  - `test_board_*` for the ESP32-C3 cover the ESP32 side; see its section.
  - All board tests skip when their board is absent. They skip with "port busy" while the Windows app holds the port, so quit it first (`"%LOCALAPPDATA%\Programs\Touch Deck\TouchDeck.exe" --quit`). PASTE and the jiggler inject real keystrokes/mouse input on the PC (RP2040: always, over USB HID; ESP32-C3: in PC mode through the app), so trigger them deliberately, or turn on the app's Dry run.

**Firmware version:** `src/version.h` and `esp32c3/src/version.h` define `FW_BOARD` and `FW_VERSION`, and the `VER` serial command replies `VERSION <board> <version> <build date>`. Bump `FW_VERSION` on every firmware change that ships. The Windows app (`windows-app/`) shows it and offers an RP2040 update when its bundled firmware is newer.

## Hardware facts (from the schematic, not the demo code)

Pin map lives in `src/board.h`. Non-obvious points:
- LCD is ST7789V2 240x280 on SPI1; the visible area starts at **controller row 20** (`Y_OFFSET` in `lcd.c`). Init sequence is copied from Waveshare's `LCD_1in69.c`.
- Buzzer/speaker is on **GPIO2**, AC-coupled through a 10µF cap into an SS8050 transistor. A DC level is silent; sound needs a PWM square wave. Waveshare's demo code never uses it.
- **GPIO15 (SYS_EN)** latches board power on battery; `main()` drives it high first thing.
- Touch (CST816T @0x15, chip ID 0xB5), IMU (QMI8658) and RTC (PCF85063) share I2C1 on GPIO6/7. Only touch is used. Because touch reads are INT-gated, any future IMU/RTC code on the same bus must not assume the touch chip is idle-safe to address. Time comes from `__TIME__` until the PC helper sends `TIME`.

## Architecture

**Two cores.** core0 (`main.c`) runs USB (`tud_task` via `usb_io_poll`), touch polling, and the typing/jiggler state machines — all non-blocking, time-stepped. core1 (`ui.c`) only renders and pushes frames, because a full redraw takes tens of ms and would otherwise stall HID reports. They share `app_t app` (`app.h`); `clip`/`msg` are guarded by `clip_mtx`, core0 requests redraws by bumping `app.redraw_seq`, the watch's tick is played by core0's second-alarm interrupt, and core1 pushes the frame it drew ahead on that edge.

- `usb_io.c` + `usb_descriptors.c`: one HID interface with report IDs (1 keyboard, 2 mouse) plus CDC. The CDC line protocol with the Windows app is documented at the top of `usb_io.c`. HID is device→host only; the host's single message back is the keyboard LED state, used to compensate for Caps Lock while typing.
- `typer.c`: types `app.clip` as US-layout keystrokes (TinyUSB `HID_ASCII_TO_KEYCODE`), press/release with small gaps. Non-ASCII is skipped on the board; the app transliterates before sending.
- **Jiggler letters.** `jiggler.c` drives the shared engine `jig_motion.c`, which walks the dot along a letter lane from `jig_paths.c`.
  - **Engine:** motion by arc length at about 920 box units/s with ±30% drift. Closed letters (O, B, D) loop; the rest bounce. Sideways wander within the lane follows a smoothed normal, so it never jumps at corners. The glide between letters takes 0.5 s. `jm_mouse` gives `0.12 px × scale × (dot − start)`, so the mouse stays in the area where it started.
  - **Mouse output:** relative deltas with accumulated rounding, so there's no drift from truncation.
  - **Phases:** a periodic menu event, decided by the shared, host-tested `jig_menu.c` (identical in both trees; `test_jig_menu.py`): STOP → [right-click, hold `open_s`] → key (ESC or F15) → wait `pause_s` + 300 ms → RESUME. `jiggler.c`/`.cpp` only send what it returns, advancing once the send went out. The settings (`app.jig_cfg`: menu on, key, open 0-60 s, pause 0-60 s; defaults on/ESC/2/0) come from the **Jiggler menu** panel: the cog on the Jiggler page opens it, and an X or a right swipe closes it (`ui_state_t.sub = UI_SUB_JIGSET`, DBG `jset=`). `JIG CFG m k o p` sets them over serial. RESUME picks a random different letter (`jm_pick`). A paste waits until the jiggler is back in `JIG_MOVING`, then pauses it. `ANIM 1` walks a letter on screen without HID.
  - **Letter shapes and board lane geometry** live only in `tools/jigpaths.py`. Run `python tools/jigpaths.py` and it writes `src/jig_paths.*`, `esp32c3/src/jig_paths.*` and the app's `JigPaths.g.cs`. **Never hand-edit those.** A pytest fails when they are stale.
  - **Shared files:** `jig_motion.*` and `jig_lane.*` (lane drawing: a wide wall stroke, then the inner stroke) are identical in both trees, and a pytest checks that.
- `touch.c`: classifies tap / long-press / swipe itself instead of using the chip's gesture engine. **Never read the CST816 on a timer.** Unsolicited reads wedge it within seconds, holding SDA low. Reads happen only after a TP_INT falling-edge IRQ, and finger-lift is inferred from INT pulses stopping (`RELEASE_MS`). A failed read triggers an I2C bus clear plus a chip reset. The `DBG` serial command reports touch stats without touching the chip; `python tools/clip_helper.py --debug` logs it every 2 s.
- `lcd.c`: ST7789 driver. Commands go over 8-bit SPI; `lcd_push_frame()` switches SPI to 16-bit frames and DMAs the whole framebuffer (16-bit frames give the panel's big-endian byte order for free). Always `lcd_wait()` before writing to `fb` again: it restores 8-bit mode and releases CS.
- `gfx.c`: one full-screen RGB565 framebuffer (`fb`, ~134 KB of 264 KB RAM, so double buffering won't fit). Primitives are signed-distance based and anti-aliased by blending into existing pixels, so draw order matters. Discs/rings fill solid spans and only do distance math on edge pixels. Text uses the design's typefaces (Barlow, JetBrains Mono) as 4-bit anti-aliased fonts in `aa_fonts.c`, generated by `python tools/fontgen.py`, which writes both trees. Never hand-edit `aa_fonts.*`; change sizes in `FONTS` and regenerate. Draw text with `gfx_text_aa*` and position it by the capital-letter centre (`gfx_text_aa_ytop`). `tools/tests/test_fontgen.py` checks that every UI label fits its button or circle chord, so add new labels there.
- `settings.c`: persistent settings (`muted`, `jig_on`, `jig_scale`, and since v4 the jiggler settings `menu_on`/`key_f15`/`open_s`/`pause_s`) in the last 4 KB flash sector (the second-to-last on the RP2350). Saves from taps are debounced: `settings_save_soon()` writes about 1 s after the last change, from `settings_poll()` in core0's loop (`PICO_FLASH_SIZE_BYTES - 4K`; the board has 16 MB but the `pico` board config assumes 2 MB, which is fine). Append-only 256-byte records, newest valid wins, erase only when all 16 pages are used. Writes go through `flash_safe_execute`, which requires core1 to have called `flash_safe_execute_core_init()` (first line of `ui_core1_main`) — keep that if core1's entry changes. UF2 flashing doesn't touch that sector, so settings survive firmware updates. Add new fields to `record_t` by bumping `MAGIC` and keeping a reader for the previous layout (see `MAGIC_V1`) so users don't lose settings on upgrade. A saved `jig_on` restarts the jiggler at boot via `jiggler_set(true)`; it only moves once USB is mounted.
- `ui.h` holds button/hit-area geometry shared by drawing (core1) and touch handling (core0).
- **Pages vs. frame loop (the device mirror, spec `docs/superpowers/specs/2026-09-29-device-mirror-design.md`):**
  - `ui_pages.c` draws the pages **only from a `ui_state_t`** (`ui_state.h`): no SDK, no `app`, no clock. `ui.c` keeps the frame loop and `ui_state_fill()`, which samples `app` once per frame (clip and message under `clip_mtx`, ~30 µs). Anything a page shows must be a `ui_state_t` field. Add new fields at the end of the struct, fill them in `ui_state_fill`, send them in `ui_sync.c`, and add them to the app's `MirrorState` and `tdui_host.py`.
  - `ui_state.h`, `ui_sync.h` and `ui_sync.c` are identical in both trees (a test checks this). `ui_sync.c` turns a sample into the `STATE`/`TEXT`/`CLIPTEXT` lines that `usb_state_poll` sends after `WATCH 1`. It checks every 10 ms and sends on change; the dot goes at most every 50 ms. It stops when the host closes the port.
  - `hostui/` compiles each board's `ui_pages.c` + `gfx.c` + fonts/icons/lanes into `tdui_<board>` (`build.bat` MSVC, `build.sh` clang/gcc) for the app's device mirror. MSVC, gcc and the RP2040 produce the same pixels (sinf/cosf included); keep page code plain C11 with no platform calls.
  - Streaming the framebuffer instead was measured and rejected: CDC gives ~700 KB/s, a full frame is 134 KB, and `fb` can't be touched while it is being sent.
- **Mute** silences only the once-a-second watch tick. The touch/button click (`feedback()`) always sounds.
- **Clipboard trash** (`TRASH_CX/CY`) and the `CLIP CLEAR` command call `clip_clear()`, which does nothing when the clip is empty or a paste is typing.
- **Jiggler page:**
  - the scale pill (top-left) and BOOT call `jig_cycle_scale()`;
  - the ON/OFF pill (top-right) and the letter box plus 10 px toggle the jiggler;
  - the cog (lower left) opens the Jiggler menu panel (`JS_*` geometry in each `ui.h`).
- **1.69 touch top band:** the panel squeezes its top band. A finger on y 42 reads y ≈ 2 (measured), so targets near the top (X, trash, jiggler pills) use `near_box_top()`, which reaches up to the edge.
- **App mirror protocol** (header of `usb_io.c`):
  - `WATCH 1` makes `usb_state_poll()` send `STATE jig= letter= scale= phase= x= y= clip= paste=` on any change, with the dot position at most every 100 ms;
  - `JIG ON|OFF`, `JIG SCALE n` and `CLIP CLEAR` control the board from the app.
  - Keep the ESP32's `link.cpp` identical, and update the app's `BoardLine.StateReport` when it changes.
- **Frame scheduling (core1, `ui_core1_main`):** three frame types.
  - **Full redraw:** only when core0 bumps `redraw_seq`, the page changes, or an `app_message` appears or expires.
  - **Partial redraw:** on animating pages at 20 fps. For the jiggler (on, or `ANIM 1`), that's the dot's old+new box, `dot_rect`, from one position sample per frame (`jig_draw_x/y`), plus the status strip every 250 ms. For a paste in progress, it's `CLIP_ANIM`. The page is drawn under `gfx_set_clip` and pushed with `lcd_push_rect`. Letter lanes are costly to draw in full, about 120 ms, so the jiggler page redraws fully only on letter switch, on/off, scale and page change.
  - **Watch page:** the clock second comes from a **hardware timer alarm** on core0 (`on_second` in `main.c`). It returns 1 s, so it re-arms relative to its scheduled time and never drifts. The interrupt plays the tick exactly on the second and bumps `app.second_edge`. Right after a second is shown, core1 **draws the next second ahead** into fb (clipped to the union of the old and new hands' boxes, `hands_rect`, plus `stopwatch_rect`). When it sees the edge, it only pushes that window, about 8 ms after the tick. A full redraw or a stopwatch update invalidates the prepared frame, and then that second is drawn late (a "miss"). `DBG` reports `lag=` (edge to on screen, prepared frames only), `hits=` and `miss=`. The stopwatch has its own seconds and repaints just its box through `app.watch_tick`. `watch_hands()` is the single definition of the hand geometry used by drawing and the region maths.
  - **Otherwise nothing.**
  - Every primitive honours the clip, so a clipped redraw only pays for the region. If you add something that animates, add its rectangle to the region list, or it will only update on full frames.
- **Performance:** the core runs at **200 MHz** (1.15 V). `PICO_CLOCK_ADJUST_PERI_CLOCK_WITH_SYS_CLOCK=1` keeps SPI/I2C on that clock; without it the SDK moves clk_peri to 48 MHz and the LCD push gets 2.5x slower. Drawing is software float (no FPU), so it dominates frame time. Running the gfx loops from RAM gave no gain. `gfx_line` walks only each row's capsule span, not its whole bounding box. That's pixel-identical to the original, host-tested, and cut the watch from 141 to 22 ms. `python tools/perf_rp2040.py [--watch]` forces 20 full redraws per page (a `TIME` command) and reads each one's `drawmax`, then measures the animation rates; `--watch` streams the mirror as the app does. Full-redraw times move by a few ms with code layout alone (XIP cache), so compare runs with the same letters and more than one round. `ANIM 1` animates the jiggler page without sending HID.
- **BOOT button** (`button.c`): read through the flash chip-select from RAM inside `flash_safe_execute`, so `button_init()` must run before core1 starts. On the watch, short press starts/pauses the stopwatch and long press resets it. On the jiggler page it cycles the circle scale 1x/1.5x/2x (saved in the v3 settings record). `BTN [LONG]` and `SWIPE L|R` inject these over serial for `tools/tests/test_board_rp2040.py`.
- **Visual language** matches the ESP32-C3 port: fixed amber `USB` chip (dot = `tud_mounted()`), a rounded edge ring (`gfx_rrect_ring`), and pill buttons on the Clipboard and Jiggler pages. The watch face and mute icon keep their own look. `src/icons.c` is a copy of `esp32c3/src/icons.c`; keep the two in sync.

## RP2350 round board (`rp2350-128`)

Waveshare RP2350-Touch-LCD-1.28: RP2350 (Cortex-M33 with FPU, 520 KB RAM, 16 MB flash), round GC9A01A 240x240, CST816 touch (ID 0xB5 on ours). It has **the same pins as the 1.69** (`src/boards/rp2350_128.h`). The LCD reset is GPIO 13, as in Waveshare's demo; the Pico SDK's `waveshare_rp2350_touch_lcd_1.28.h` wrongly says 12, which is MISO. There's no buzzer, power latch or RTC. Pages: a silent round watch (BOOT runs its stopwatch), Clipboard, Jiggler.
- **Build:** `cmake -S . -B build-rp2350 -G Ninja -DCMAKE_BUILD_TYPE=Release -DTD_BOARD=rp2350_128`, then `ninja -C build-rp2350`, giving `build-rp2350/deck128.uf2`. `TD_BOARD` defaults to `rp2040_169` (`build/watch.uf2`). The SDK fixes the chip per configure, so each board has its own build directory. The RP2040 source list stays in its original order: link order sets the flash layout, which shifts draw timings.
- **One tree, per-board headers:**
  - `board.h`, `ui.h`, `ui_pages.h`, `jig_paths.h` and `version.h` switch on `TD_BOARD_RP2350_128` / `TD_ROUND`. A quoted include finds the including file's own folder first, so shared `src/*.c` always get these switches.
  - `src/round/` holds **byte copies** of the ESP32-C3's `ui_pages.c/.h` and `ui.h`, plus the generated `jig_paths.h`. `test_ui_host.py` keeps them identical, so change them in `esp32c3/src/` and copy.
  - `UI_USB_ONLY` gives 2 pages (`UI_PAGE_COUNT`) and a `USB` chip.
  - `main.c`/`ui.c` compile the watch, buzzer and power-latch paths out under `TD_ROUND`.
  - `lcd.c` holds both panels' init sequences. The GC9A01A one is converted from Waveshare's `LCD_1in28.c`, and the round panel has no row offset.
  - `button.c` reads QSPI CSN at bit 27 of `gpio_hi_in` on the RP2350 (bit 1 on the RP2040).
- **Identity:** `VER` says `rp2350-128`. The USB ID is the same `CAFE:4011` as the 1.69, so tools and the app choose by `VER`:
  - `touchdeck.find_board(model)`;
  - `flash.py --board rp2350-128`;
  - `perf_rp2040.py --board rp2350-128`.

  Both firmwares embed `TDBOARD:<model>;` as Pico binary info. The app checks it before flashing.
- **Bootloader:** a drive whose `INFO_UF2.TXT` has `Board-ID: RP2350`, USB `2E8A:000F`. Waveshare's factory demo is a stock SDK program (`2E8A:0009`, COM port) that reboots to the bootloader when its port is opened at 1200 baud. `picotool` only reaches the board before Touch Deck is on it; afterwards use `flash.py` (BOOT over serial). The factory firmware is backed up at `%USERPROFILE%\.touchdeck\backups\rp2350-touch-lcd-1.28-factory.uf2`.
- **Settings sector:** the second-to-last flash sector on the RP2350 (`settings.c`). SDK 2.x RP2350 UF2s end with an RP2350-E10 workaround block at the top of flash, and writing it erased the last sector, so settings kept there were lost on every install. The RP2040 keeps the last sector.
- **Tests:** `test_board_rp2350.py` and `test_board_mirror_rp2350.py` (FBCRC host vs board). They skip when no `rp2350-128` answers.
- **Performance:** about 10x the RP2040. A full jiggler page is 9-12 ms, the clipboard 5.8 ms, and the jiggler animation holds 19.7 fps at 1 ms per frame.

## ESP32-C3 port (`esp32c3/`)

This is a PlatformIO project (Arduino-ESP32 2.0.17, LovyanGFX, NimBLE-Arduino 1.4) for the ESP32-2424S012C: ESP32-C3, 1.28" round GC9A01 240x240 screen, CST816D touch (chip ID 0xB6). It has Watch, Clipboard, Jiggler and Settings screens (the round watch is silent and needs the app's TIME: no RTC). The board has no speaker and no real-time clock.
- Build: `cd esp32c3 && python -m platformio run`. Flash: `python -m platformio run -t upload --upload-port COM7`. No BOOT button needed; esptool resets the chip over USB. Stop `clip_helper.py` first, because it holds the port.
- **HID goes over Bluetooth LE, not USB.** The C3 has no USB device controller, only a fixed USB-Serial-JTAG at `303A:1001`. The USB cable carries only the app's serial protocol. `ble_ready()` means connected and subscribed. In BT mode, typing and jiggling wait for it.
- **Pairing is explicit** (Settings → Bluetooth row → Bluetooth sub-page). `ble_hid.cpp` keeps a state machine: `BT_UNPAIRED` (not advertising at all), `BT_PAIRING` (advertising for 120 s with a random 6-digit passkey on screen), `BT_WAITING` (bonded, advertising for that PC), `BT_CONNECTED`, and `BT_OFF` (the user tapped Disconnect, bond kept). It uses DisplayOnly + MITM, and outside pairing mode `onPassKeyRequest` returns an unseen random code, so strangers can't pair. It keeps one bond: Pair and Forget delete all bonds. After Forget, the PC must also remove the device on its side. The PC's name is read from its GAP Device Name (0x2A00) after pairing and stored in `Preferences` key `host`. `python -m pip install bleak` gives a BLE scanner for checking whether the board is advertising.
- **Opening the C3's port must keep DTR and RTS low.** Those lines are its reset and boot-mode lines. `tools/touchdeck.open_serial()` handles this: DTR high for the RP2040, whose TinyUSB only transmits when DTR is set, and low for the ESP32.
- `CORE_DEBUG_LEVEL=0` is required, because Arduino core log lines on `Serial` corrupt the serial protocol.
- Code layout mirrors the RP2040 firmware: `ui_pages.c` draws from a `ui_state_t`, `ui.cpp` has the frame loop and `ui_state_fill()`, and `link.cpp` streams the mirror like `usb_io.c` (plus `TEXT host`/`down`). `gfx.c` is a copy (the framebuffer is heap-allocated in DMA-capable RAM), `touch.cpp` is the same interrupt-gated CST816 driver, and `typer`/`jiggler` are the same state machines with slower Bluetooth pacing (12 ms key hold/gap, 15 ms mouse step). The Arduino `loop()` runs at priority 2 for logic; `ui_task` renders at priority 1, because the C3 has one core and no FPU. The layout has to stay inside the 240 px circle.
- **UI** follows the approved mockup (https://claude.ai/artifact/QbZAqAnnHaYKeZfYejQRWz): an edge ring and top chip in the mode colour (amber PC, blue BT) with a link-health dot, pill buttons, three pages (Clipboard, Jiggler, Settings) plus the Settings > Bluetooth sub-page. All hit/draw geometry lives in `ui.h`, and line icons in `icons.c` (plain C, shared with the RP2040 tree). The round watch (page 1, shared with the RP2350) shows TIME FROM PC until the app sends the time.
- Settings: `Preferences` namespace `touchdeck`, keys `jig` (jiggler on/off, restored at boot), `jscale` (0-2) and `mode` (0 = PC, 1 = BT).
- **Output mode is the single source of truth** (spec: `docs/superpowers/specs/2026-09-24-output-mode-design.md`). `typer` and `jiggler` only call `out_key` / `out_mouse` / `out_ready` in `output.cpp`. BT sends Bluetooth HID reports. PC sends `K <mod> <usage>` / `M <btn> <dx> <dy>` lines, which the Windows app performs with `SendInput` (`TouchDeck.Core/Input/Injector.cs`, scancodes). The app reports Caps Lock back as `LEDS`. BT is selectable only while bonded. A saved BT with no bond, and Forget, both fall back to PC. Switching mode stops a paste and releases anything held on the old destination.
- **Jiggler and clipboard** as on the RP2040: letter lanes with the pills beside the letter, a trash can at (178,42), and the same `WATCH`/`STATE`/`JIG`/`CLIP CLEAR`/`ANIM` commands in `link.cpp`. Scale is new on this board: tap the pill; it's saved in `Preferences` key `jscale`. `gfx.c/h` are the RP2040 copy (clip API, `gfx_line` spans) with a heap `fb`. `ui_task` pushes partial frames of the dot and status strip with `display_push_rect`, and full frames on changes.
- **Board tests:** `test_board_*.py` drive the ESP32-C3 over COM7 with the scripting commands `MODE PC|BT`, `TAP x y`, `SWIPE L|R`, `TEXTW`, `WATCH`, `JIG`, `CLIP CLEAR`, `ANIM` and `DBG` (it reports `mode=`, `jig=`, `leds=`, `jscale=`, `letter=`, `clip=`). They skip when the board is absent, and the unpaired-only checks skip while a Bluetooth bond exists. They skip while the Windows app holds the port, so quit it first. PlatformIO is installed under `python` (3.9), not `py`.
